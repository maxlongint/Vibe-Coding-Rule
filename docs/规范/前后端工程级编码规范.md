# 前后端工程级编码规范

本文档用于 TypeScript、前端、后端、API 与安全相关任务，约束 AI 和开发者输出健壮、可维护、安全且可验证的工程代码。它不替代具体技术栈、业务规则、接口文档、工具配置或根目录 `AGENTS.md`。

涉及设计取舍时，先按《代码设计原则》判断；本文只保留实现和交付时需要主动核对的工程检查项。

## 适用边界

- 只收录跨项目、跨技术栈稳定成立的规则。
- 能交给格式化、lint、类型检查或安全扫描的规则，优先落到工具配置。
- 本文不替代用户已确认需求、OpenSpec change、当前源码、测试结果或安全权限约束。

## 总目标

工程级代码必须同时满足：

- **业务正确**：实现已确认目标，不改变未授权的接口、数据、权限、错误语义、性能和兼容性。
- **边界清晰**：展示、状态、业务规则、数据访问、外部依赖、权限和错误处理职责清楚。
- **错误显式**：输入异常、依赖失败、权限不足、契约缺失和状态冲突不得被默认值、空对象、mock、旧链路或吞错掩盖。
- **安全可靠**：默认不信任外部输入，敏感信息最小化处理，关键写操作防重复。
- **可验证**：修改能被测试、类型检查、构建、lint 或手工验收覆盖；未验证项必须说明。

## 实施流程

1. **识别边界**：目标行为、非目标不变式、入口、数据来源、权限、错误模型、外部依赖和验证方式。
2. **设计契约**：模块边界、类型边界、接口字段、状态流转、失败路径、幂等或并发策略。
3. **最小实现**：沿用既有模式，收紧类型和校验，显式处理错误，不绕过权限，不引入未标明边界的 mock。
4. **覆盖验证**：按风险运行测试、类型检查、lint、构建或手工验收，并读取完整结果。
5. **交付说明**：说明实际改变、直接相关不变式、验证证据、未验证项和剩余风险。

## 核心检查项

### 健壮性

- 外部入口区分正常路径、失败路径、边界值和不可恢复错误。
- 输入缺失、类型错误、格式错误、越权访问、资源不存在、状态冲突、速率限制和依赖失败分类处理。
- 数据库、缓存、队列、文件系统、对象存储和第三方 API 调用明确超时、重试、幂等、部分成功和回滚边界。
- 关键状态变更必须确认最终结果，不因本地函数返回成功就假定远端写入、异步任务或副作用已完成。
- 只有业务上确实无数据时才能返回空；依赖失败、解析失败或权限失败必须暴露为错误。

### 可维护性与扩展性

- 稳定业务规则、协议适配、权限判断、数据访问和外部服务调用集中在清晰边界内。
- 公共模块只暴露必要能力，不泄漏数据库表结构、第三方 SDK、页面状态或接口偶然返回结构。
- 复杂流程拆出可单独验证的输入校验、权限判断、状态流转、外部调用和响应适配步骤。
- 注释只解释安全边界、接口兼容、失败处理、幂等策略和非显然副作用。

### TypeScript 与类型安全

- 避免滥用 `any`、`unknown as X`、非空断言、宽泛类型断言和 `@ts-ignore`；确需使用时说明边界、原因和验证方式。
- 外部输入、持久化数据、跨服务响应、URL 参数、表单数据、文件内容和环境变量必须在可信边界运行时校验。
- 区分输入类型、领域类型、持久化类型和响应类型；数据库模型、接口 DTO 和 UI 状态不要互相泄漏实现细节。
- 可选字段、空值、缺省值和状态枚举必须语义明确；不得让 `null`、`undefined` 或空字符串混合表达多个含义。
- 公共 API 导出类型应稳定；删除字段、改变含义、放宽或收紧必填性都按兼容性影响处理。

### 接口契约

- 前后端或跨服务接口先明确资源语义、请求参数、响应字段、必填/可选、空值含义、错误响应和权限要求。
- HTTP 方法、状态码、错误码和响应结构保持一致；同类错误不返回不同语义。
- 新增字段优先兼容扩展；删除字段、改类型、改必填性、改错误语义、改资源路径或分页方式属于潜在破坏性变更。
- 列表接口明确分页、排序、过滤和游标语义；客户端不依赖未声明默认顺序或后端内部实现。
- 写接口明确幂等、防重复提交、并发冲突和重试语义；支付、发布、删除、权限变更等关键操作必须确认最终结果。
- 接口适配集中在 API client、adapter、repository 或项目既有等价层，不在页面、组件和业务服务中散落解析同一协议。

### 安全编码

- 前端校验只用于交互体验，不能替代后端或可信边界校验。
- 身份认证、权限授权、资源归属、租户或组织边界、状态机、金额、数量、时间范围、文件类型和大小等关键字段必须在可信边界验证。
- 用户可控内容进入数据库、HTML、URL、日志、Shell、文件路径、模板、HTTP Header 或第三方 API 前，使用对应上下文的参数化、编码、转义或允许列表。
- 安全校验默认拒绝；字段缺失、配置缺失、解析失败或依赖异常时不能默认放行。
- 密钥、令牌、连接串、生产地址和私有凭据不得写入源码、文档、测试快照、日志或提交说明。
- 用户可见错误不暴露密钥、令牌、连接串、堆栈、内部路径、权限细节或未脱敏个人敏感信息。

### 后端服务

- 依赖显式声明并可复现安装，不依赖开发机全局包、隐式运行环境或未记录的本地配置。
- 配置来自环境变量、配置中心或项目约定配置系统；缺失、格式错误或权限不足应启动失败或显式报错。
- 构建、发布和运行阶段可区分；运行时不依赖源码目录里的临时生成物或手工步骤。
- 服务日志保留排查上下文，但不替代错误处理或泄露敏感信息。
- 后台任务、迁移脚本和管理命令应可重复执行或具备防重机制，并明确执行环境、输入、影响范围和失败处理。
- 分层边界清晰：路由或控制器处理协议接入，业务服务处理规则，数据访问层处理持久化，外部适配层处理第三方差异。

### 前端工程

- 组件围绕展示、交互或容器职责组织；复杂业务规则、请求适配和跨页面状态不堆在组件中。
- 能由已有数据推导的状态不重复存储；必须缓存或冗余时，明确刷新、失效和一致性策略。
- 表单处理初始值、输入约束、提交中、提交失败、重复提交、服务端校验错误和成功反馈。
- 网络请求通过项目约定的数据访问层统一处理认证、错误、取消、重试、超时和响应解析。
- 权限控制不能只靠隐藏按钮、禁用控件或路由拦截；真实权限操作必须由后端或可信边界再次校验。
- UI 不依赖后端未声明字段、未声明排序、内部枚举值或偶然返回结构。
- 用户可见错误应可理解、可恢复；内部细节只进入受控日志或监控。

## 伪高级代码禁区

- 用 `any`、类型断言、非空断言、可选链堆叠或默认值让错误消失。
- 把所有错误合并成“系统错误”，或把依赖失败伪装成空数据。
- 为了通过测试只改断言、删测试、跳过校验或弱化必要检查。
- 在生产或真实业务链路引入未标明边界的 mock、seed、本地缓存或旧链路。
- 把数据库模型、第三方 SDK 返回值、页面状态和接口响应混成同一个对象到处传。
- 只在前端隐藏入口，却省略后端或可信边界的权限校验。

## 测试与验证

- 验证结论只能来自实际执行结果。
- 纯逻辑优先单元测试；接口契约优先集成或契约测试；关键用户路径优先端到端或等价验收。
- 新增或修改权限、数据契约、错误处理、状态流转、金额数量、后台任务、外部集成时，覆盖成功路径和关键失败路径。
- 不得跳过、删除或弱化测试，不得仅修改断言和期望值制造通过结果。
- 交付前运行能证明本次改动的类型检查、lint、测试、构建或手工验收命令，并读取完整结果。
- 验证失败、无法执行或覆盖不足时，说明原因、影响、未覆盖项和剩余风险。
- 测试中的 mock、fixture、seed 和本地模拟必须隔离并标明边界。

## AI 输出约束

- 先识别项目既有架构、调用方式、错误模型、测试方式和直接相关不变式。
- 把“高级、健壮、可扩展、易维护、安全”拆成本文检查项，并落实到设计、实现和验证。
- 发现真实失败、依赖缺失、权限不足、契约不清或验证无法执行时，明确暴露，不伪装成功。
- 不能确认业务语义、权限边界、破坏性兼容影响或需求承接关系时，停止并请求用户确认。
- 完成后说明实际改变、已核对的直接相关不变式、验证证据、未验证项和剩余风险。

## 使用方式

- TypeScript、React、Node.js 或全栈实现前，对照“总目标”“实施流程”“核心检查项”。
- 安全相关任务重点核对“安全编码”。
- 后端服务、配置、部署和运行问题重点核对“后端服务”。
- 前后端联调、API 新增或变更重点核对“接口契约”。
- UI、页面、交互、状态管理和数据请求重点核对“前端工程”。
- PR、代码评审和交付前检查重点核对“测试与验证”“AI 输出约束”。
