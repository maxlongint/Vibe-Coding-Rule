# 项目规范文档（docs/）

> 来源：Vibe Coding Rule 规范包自带文档。接入业务项目后，请保留本标记；业务项目自行新增、生成或沉淀的文档不要使用本标记。

本目录是按索引读取的长期项目知识库，存放长期有效、跨需求适用且已经稳定确认的项目规范，例如技术栈、架构、业务规则、环境约束和条件化协作流程。

## 收录边界

单次需求、临时计划、尚未确认的方案以及进行中的 proposal、tasks 不属于项目规范。AI 每次 Chat 都需要知道、在读取本索引前必须生效，或用于判断是否读取本目录和是否允许继续的规则也不属于本目录，必须写入项目根目录 `AGENTS.md`。新增或移动文档前，应确认其职责单一、内容长期有效；不符合条件时使用正确载体，不擅自收录、移动或删除。

Vibe Coding Rule 规范包自带文档应保留标题下的来源标记。业务项目自行新增、生成或沉淀的 `docs/` 文档不得使用该标记，应通过文件路径、标题或索引说明表达项目自身归属。

AI 工具或个人环境默认安装的全局能力、内置 skill、Superpowers 目录及其附带文档，不属于 `docs/` 项目规范；不得为补全索引或扩大上下文而复制、迁移或收录，除非用户明确要求并确认归属。

安装、部署和排障步骤如需长期维护，应与框架说明、架构规则等稳定知识分开，分别注明适用场景。

## 读取方式

由项目根目录 `AGENTS.md` 判断当前任务是否需要项目特有知识或条件化流程。只有任务确实需要，或 `AGENTS.md` 明确触发时，才读取本文件，再按索引选择与任务直接相关的文档；不得在每个 Chat 中默认加载本目录。与任务无关、索引未指向的文档不为扩充上下文而加载。

新增、移动、改名或删除规范时，同步维护索引。链接失效、内容不可读或规范冲突时显式说明，不猜测缺失内容。

## Node.js 版本与外部流程工具

当项目固定 Node.js 版本时，应区分“项目运行时/构建工具链”和“外部开发流程工具”的运行时要求。

项目源码构建、测试、lint、格式化以及 npm/pnpm/yarn 脚本必须优先使用项目声明的 Node.js 版本。若项目存在 `.node-version`、`.nvmrc` 或等效约定，应先按项目要求切换或通过版本管理器执行相关命令。

不参与项目构建产物、仅用于需求管理、索引、分析或辅助流程的外部 CLI 工具，可按该工具自身官方要求使用独立运行时。执行前必须说明该工具不属于项目运行时链路，并用实际命令验证其可用性；不得把外部工具的 Node.js 版本要求误判为项目 Node.js 版本要求，也不得用项目 Node.js 版本强行运行不兼容的外部工具后声称工具不可用。

例如 OpenSpec CLI 属于需求流程工具，不参与 Angular 项目构建；当项目 Node.js 固定为 14.x 而 OpenSpec CLI 要求 Node.js 20+ 时，可使用 Node.js 20+ 执行 OpenSpec 命令，同时项目构建、测试和包管理命令仍必须使用项目声明的 Node.js 版本。

## 与进行中需求载体的区别

| 载体 | 放什么 | 使用方式 |
| --- | --- | --- |
| `docs/` | 相对稳定、跨需求有效的项目规范 | 按本索引选择性读取 |
| OpenSpec change（唯一） | 用户已明确确认的新增需求或需求变更，以及该需求后续的目标、范围、验收、设计、任务和变化记录 | 新增需求由用户在口径确认后主动授权创建并通过冲突检查；需求变更或已有需求由用户确认继续原 change / 新建关联 change，新建关联 change 同样由创建请求授权生成 ID 和检查冲突；同一需求只对应一个 change |

长期架构约定不应只留在进行中需求载体；确需沉淀时，在验收后合并进本目录。

## 按需组织

仅在存在实际内容时创建子目录，不预建空目录。常见目录包括：

- `架构/`：模块关系和关键设计决策；
- `规范/`：编码与协作规范；
- `experience/`：项目结束、阶段复盘或问题沉淀后形成的经验包 Markdown。

经验包不是 skill，也不是 AI 可自行追加的记忆区。只有用户明确要求保存，并指定或确认归属时，才能把复盘结论写入 `experience/` 或其他长期文档；后续确需由 AI 按固定流程调用时，才提炼到 `.agents/skills/`。
